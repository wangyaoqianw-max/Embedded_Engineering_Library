# 嵌入式项目 C 代码设计规范

## 资产简介

本资产是一份面向嵌入式 C 项目的代码设计、实现、评审和维护规范，覆盖分层、数据模型、命名、接口、内存、错误处理、中断、DMA、RTOS、硬件、可移植性、日志、第三方代码和质量工具等主题。

## 来源与版本

- 整理者：仓库维护者。
- 编写方式：由维护者确定目标和工程原则，使用 AI 辅助整理。
- 第三方代码来源：未使用已识别的具体第三方规范作为直接改编基础。
- 当前版本：`V2.0`。

本资产采用 [MIT License](../LICENSE)。引用外部标准、厂商规则或项目规范补充内容时，应记录具体来源及其授权条件。

## 目录内容

- `嵌入式项目C代码设计规范V2.md`：规范正文，包含规则优先级、适用范围、20 个主题章节和 Code Review 检查项。

## 依赖与适用环境

本文档不依赖特定 MCU、编译器或 RTOS，但实际采用时需要结合目标芯片、工具链、团队约定、厂商生成代码和第三方库规则进行裁剪。

## 使用方式

1. 项目启动时先确定适用章节及规则等级，不要求所有项目机械套用全部内容。
2. 在项目 README、贡献指南或 CI 配置中记录对本规范的裁剪和例外。
3. Code Review 按正确性、安全性、实时性、架构和风格的顺序检查。
4. 能由编译器、格式化器或静态分析工具检查的规则，应尽量转化为工程配置。
5. 规则与芯片手册、编译器 ABI、RTOS 文档或项目验证结果冲突时，以经过确认的工程事实为准，并记录例外原因。

## 适用边界

- 适合作为个人项目或团队规范的起点、Review 清单和培训材料。
- 它不是 MISRA C、CERT C 或任何功能安全标准的替代品，也不代表合规认证。
- 文档中的行数、嵌套层数、命名和格式规则属于工程默认值，不应凌驾于正确性、现有稳定 API 或第三方代码约定。
- 对 HAL、CMSIS、RTOS、Vendor SDK 和自动生成代码，应优先保留其原有规范。
- 文档本身不会自动约束工程，仍需通过编译选项、格式化、静态分析、测试和 Review 落地。

## 已知限制

- 尚未提供配套 `.clang-format`、静态分析规则、CI 模板或可执行检查脚本。
- 部分规则具有项目偏好性质，迁移到其他团队前需要评审。
- 当前仓库的“五层架构”示例仍重新定义了若干标准类型，与本文档第 7.2 节不一致，说明规范尚未在示例代码中完全落地。
- 文档未逐条映射到 MISRA C、CERT C 或特定公司的正式编码标准。

## 复用性评审结论

该规范覆盖面完整，适合作为嵌入式 C 项目的默认评审框架，复用价值较高。它的最佳复用方式是“按项目裁剪并转化为工具配置和 Review 清单”，而不是不加区分地作为强制标准。后续应优先补充可执行检查配置，并修正示例代码与规范之间的已知冲突。
